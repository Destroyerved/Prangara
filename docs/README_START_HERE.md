# PRANGARA — START HERE

This folder is the working specification for the expanded PRANGARA platform.

## Read in this order

1. **PRD.md** — complete product definition, features, architecture and acceptance criteria.
2. **task.md** — role-wise work split for 2 frontend + 2 backend engineers.
3. **DATA_RAG_COMPLIANCE.md** — data sources, provenance, RAG, compliance events and evaluation.
4. **AI_AGENT_PLAYBOOK.md** — rules for using Claude, Gemini, Codex/Astra or other coding agents safely.

## Product spine

> **Measure → Detect → Decide → Connect → Implement → Verify**

The original PS10 carbon engine remains the brain of the system. Marketplace, logistics, compliance and network features exist to help factories act on the recommendations and prove the result.

## P0 must remain functional

- factory intake
- Scope 1/2/3
- uncertainty
- leak detection
- peer benchmarking
- circular recommendations
- blocking/capping
- economics
- interaction de-rating
- MACC
- Sankey
- source traceability

## Team mapping

- FE-1: web/dashboard
- FE-2: APK/mobile
- BE-1: platform/API/carbon integration
- BE-2: data/RAG/compliance/optimization

## Claim boundaries

PRANGARA is screening, decision support, implementation support and evidence/readiness support.

PRANGARA is **not** a BEE-accredited audit, legal assurance service, regulator, carbon-credit verifier, or substitute for a site engineering study/vendor quotation.
